P025 项目问答

为什么 SQLite 分成专用写线程和有界读执行器？

面试时这样回答

写库可能等待事务和磁盘，查询也可能很慢，所以两者都不能直接放在 I/O 回调或 GatewayCore 业务任务中。写连接由 TelemetryPipeline 写线程串行使用；HTTP 业务提交查询任务，由独立读执行器使用只读连接并异步返回值对象。

数据库尝试启用 WAL，允许条件成立时读写并行，但仍受单写者、锁和检查点限制。一个读线程能避免同一读连接的语句状态被多个线程同时使用；有界任务队列则使持续慢查询时可以明确拒绝新任务，而不是无限堆积。

P026 项目问答

批量写库怎样兼顾吞吐与低负载延迟？

面试时这样回答

写线程先阻塞等第一项数据，取得后立即继续取当前已经排队的任务，合并成一批写入。暂时没有更多数据就提交，不额外等一个固定攒批窗口，所以低负载的一条数据不用为了凑数量再等几十毫秒。

有积压时自然合批，减少事务次数；累计达到行数阈值或遇到切库任务，就先提交当前批。切库是顺序边界，边界前的数据留在旧库，不能为了多合几行把它跨过去。

P027 项目问答

现在数据库能保证整批成功和断电不丢吗？

面试时这样回答

不能这样保证。SQLite 本身提供事务能力，但当前封装在 BEGIN 失败后仍继续逐条尝试，单条 INSERT 失败只记日志并继续，COMMIT 失败再尝试回滚；接口也没有返回具体成功数量。因此上层无法据一次函数返回判断这一批是否全部可靠写入。

另外，WAL 配合 NORMAL 主要平衡性能与安全，整机掉电时最近提交仍可能回退。进程崩溃和整机断电是不同故障，不能因为数据库通常能恢复，就宣称刚收到的所有遥测都已持久保存。

P028 项目问答

HTTP 查询为什么按设备和时间建联合索引？

面试时这样回答

常见查询是某个指标最近若干条数据，所以索引按 device_id、ts 组织。数据库可先定位指标，再按时间方向读取有限记录，减少全表扫描和排序；结果数量也有接口层约束，避免一次查询把大量历史数据搬进内存。

参数通过预编译语句绑定，返回给调用者的是复制好的值对象，不借用 SQLite 当前行的临时缓冲。预编译解决参数解释和部分重复解析成本，索引解决数据访问路径，两者作用不同。

P029 项目问答

配置热加载怎样离开 Reactor，还剩哪些非原子边界？

面试时这样回答

SIGHUP 由串口 Reactor 读取后仅调用 requestReload。gateway-control 顺序执行配置读取、数据库与 MQTT 构造、串口候选准备；同一重载未完成时合并新请求。准备成功的串口通过队列和 eventfd 交回 Reactor，只有 termios 应用、fd 注册、链路状态失效和资源交接在所属线程执行。

这仍不是所有资源的事务切换。ConfigManager 先发布新快照，再分别处理资源；数据库等写线程处理 SwapDb 才生效，串口等 Reactor 消费替换任务才生效，MQTT 还要区分连接 API 返回和 CONNACK。某项失败可以保留旧资源，HTTP 监听端口目前也不会动态重绑。

P030 项目问答

切换数据库时，队列里已经存在的数据写到哪里？

面试时这样回答

gateway-control 先构造候选读写连接，再把 SwapDb 放入遥测写队列。写线程处理到切库指令时先提交旧批次，再换写连接，指令前后数据分别按队列顺序进入旧库和新库；入队成功只是接纳切换任务。

读连接在写线程完成切换后的回调中原子发布。GatewayCore 提交查询时取得读连接快照，query 线程用该快照执行；已经排队的查询可继续读旧库，后续取得新快照的查询才读新库，不会因为全局指针替换而失去连接。

P031 项目问答

串口热重开怎样准备候选并由 Reactor 安全接管？

面试时这样回答

gateway-control 在后台构造新的 NodeLink，仅完成串口 open 并延迟 termios 设置，再把候选放入有界替换队列并通知 eventfd。准备失败或替换队列满时不交付候选，当前 Reactor 继续持有旧链路；不会由 control 直接修改旧链路的窗口或 epoll 注册。

Reactor 收到候选后注销旧 Channel，调用 activate 应用 termios；失败恢复旧注册，成功则结束旧会话并暂存协议动作，接管候选并注册实际 fd 后才推进新握手。旧 NodeLink 析构丢弃输出，旧请求终态由 start 生成的动作交给 Core。新对象有自己的解析与发送状态，旧线路的半帧和输出不能直接拼到新线路上。

P032 项目问答

异步日志具体减少了什么开销？满了和退出时怎么办？

面试时这样回答

业务线程把日志追加到内存缓冲，后台线程批量写出。关键是只在锁内交换缓冲所有权，可能阻塞的 write 放在锁外执行，因此磁盘或标准错误输出较慢时，不会直接把那段写入时间都变成业务线程持锁时间。

缓冲和队列都有上限。后台跟不上时，当前实现裁剪待写队列尾部的缓冲块，并记录丢弃数量；析构会通知后台退出、等待线程，并尝试排空剩余内容。这个选择控制了内存增长，但日志不是无损审计存储。

P033 项目问答

systemd 在这个项目里解决什么问题？

面试时这样回答

网关作为前台进程运行，由 systemd 管理启动、退出后的重启和日志收集。服务配置还建立专用状态目录，并限制文件系统与运行权限，把程序本身的业务逻辑和进程管理分开。

串口访问需要相应设备权限，数据库目录也必须可写。部署时应把“进程启动了”“串口打开了”“Broker 连上了”分开确认；network-online 的启动顺序依赖不等于 MQTT 服务已经可达。
