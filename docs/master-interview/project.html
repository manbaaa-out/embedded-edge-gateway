P001 项目问答

请用两分钟介绍这个网关与节点项目。

面试时这样回答

这是一个由 Linux 网关和 STM32 节点组成的采集与控制系统。节点用 FreeRTOS 管理传感器采集、命令处理和串口发送；网关接收节点数据，转换后上传 MQTT 并写入 SQLite，同时提供 HTTP 查询。反方向，云端命令通过网关下发到节点，节点执行后把结果返回。

网关采用多个 I/O 事件循环加一个共享业务线程：串口 epoll、MQTT 网络循环和 Boost.Beast/Asio HTTP 分别管理通信，GatewayCore 顺序处理设备业务，SQLite 查询和写入交给各自执行线程。控制链使用带会话号的 SR 协议，区分“已接收”和“已执行”，处理丢帧、重复和超时。

P002 项目问答

一条温湿度数据从节点到云端和数据库，具体怎么走？

面试时这样回答

采样任务先通过传感器服务读取数据，并拿到温湿度是否有效的标志。有效值转换成协议规定的整数单位，编码成一条完整帧，再按值复制进发送队列，由发送任务统一写串口。这样采样任务不直接和其他任务抢发送口。

网关串口 Reactor 增量拼帧并检查 CRC，将完整遥测帧和接收时间交给 GatewayCore。业务线程解码温湿度、生成 MQTT 消息并提交数据库写入；HTTP 的历史查询另交读执行线程，SQL 不在串口、HTTP 或业务线程直接执行。

P003 项目问答

一条云端查询命令怎样形成完整闭环？

面试时这样回答

MQTT 网络回调复制并投递 topic/payload，GatewayCore 在业务线程调用 translateCommand，再向串口命令队列提交内部命令并用 eventfd 唤醒。串口 Reactor 在会话就绪、窗口有空间时分配链路序号、组帧并发送。节点先保存命令并确认接收，再按序执行业务。

节点把结果存入缓存后尝试发回。串口 Reactor 处理 SR 状态与结果确认，把已完成命令事件交给 GatewayCore 映射数据、返回码和云端应答。网络循环负责实际 MQTT 收发；各线程都不为等待节点回应而阻塞。

这里哪一个 ACK 表示执行成功？

SR_RECEIVED 只表示节点保存请求。业务结果的返回码与数据才描述执行结局；SR_RESULT_ACK 主要用于节点释放结果缓存。收到重复结果仍须确认，但不能重复完成上层请求。

P004 项目问答

这种架构属于哪种 Reactor 模式，为什么共用业务线程？

面试时这样回答

整个网关仍在一个进程内，串口、MQTT 和 HTTP 各有 I/O 事件循环，因此属于多事件循环、多线程架构。它按通信通道分工，各循环把应用事件交给同一个 GatewayCore；不是主 Reactor 接连接后交给子 Reactor，也不是每个循环各配一个业务线程。

共用业务线程是因为这些入口经常涉及同一设备、同一命令。业务处理顺序集中在一个线程，链路窗口由串口 Reactor 独占，SQL 由独立读写线程负责，资源准备和 MQTT 发布/替换由 control 线程串行管理。这样按状态归属和阻塞资源划分，比仅按 MQTT、HTTP、串口入口各建业务池更容易解释一致性。

P005 项目问答

哪些资源由谁拥有，怎样避免多处同时操作？

面试时这样回答

串口 fd、输出缓冲和 CommandTracker/SR 状态由串口 Reactor 操作；MQTT 网络回调只交接消息，GatewayCore 做应用转换；HTTP 连接由 Asio 循环管理，业务线程通过完成函数返回响应。SQLite 写连接和读查询分别由专用执行线程串行使用；普通 MQTT 发布与客户端替换统一交 control 管理。

P007 项目问答

串口 Reactor 与业务线程的职责怎样严格区分？

面试时这样回答

串口 Reactor 管非阻塞读写、增量拆帧、CRC，以及会话、序号、窗口、确认和重传这些链路状态。GatewayCore 管命令解释、遥测单位转换、MQTT topic/payload、业务结果映射和 HTTP 路由；SQLite 查询与写入再提交专用执行线程。

链路处理留在 Reactor，是因为它紧贴部分写完成、收到 ACK 和超时扫描，需要单一状态所有者。收到遥测帧或完成事件后只交接消息，不在串口回调中格式化业务结果。业务提交命令后继续消费其他事件，不阻塞等节点响应。

P008 项目问答

MQTT 到业务线程再到串口，为什么需要两次消息交接？

面试时这样回答

MQTT 网络回调先把拥有独立存储的原始消息交给 GatewayCore；业务线程被任务队列的条件变量唤醒，解释命令后才提交串口下行队列并写 eventfd。第一段隔离 MQTT 收发与业务解析，第二段保证串口和链路状态只由串口 Reactor 修改。

串口 Reactor 被唤醒后以实际队列与链路许可为准消费命令，不把 eventfd 计数当作命令数量。一次只处理有限批次，仍有可处理任务就重新安排；会话未就绪或 SR 窗口满则等链路状态推进，避免没有发送能力时忙循环。

P035 项目问答

三个任务的优先级为什么这样安排？中断优先级又怎么算？

P044 项目问答
