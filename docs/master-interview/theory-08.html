外设、DMA 与传感器

T072 原理问答

UART 为什么无需时钟线，115200 能传多少有效数据？

UART 通过起始位让接收端对齐一帧，再按约定波特率采样数据与停止位。它没有随线传输的时钟，因此两端时钟误差、采样方式和电气质量都会影响可靠性。

原理与成立条件

UART 一字节在线上占多少位

异步 UART 用起始位建立采样相位，再传数据位、可选校验位和停止位，没有独立时钟线。8N1 是 1 起始+8 数据+1 停止，共 10 位；115200 baud 在这种二值编码下理论约 11520 字节/秒。应用有效负载还需扣帧头、校验、确认和空闲，不能把波特率直接当字节率。

波特率误差为何积累

接收方检测起始边沿后按本地时钟采样，各位没有独立同步。收发时钟偏差会让采样点逐渐偏离位中心，叠加抖动、噪声和边沿缓慢可能误码。允许误差与帧长、过采样实现和时序余量有关，不宜对所有 UART 一律背同一个百分比。

TXE 与 TC 的区别

TXE 表示数据寄存器可以接收下一个数据，移位寄存器可能还在发送；TC 才反映发送器按手册定义完成最后一帧位传输。DMA TC 又只是 DMA 搬运结束，最后字节可能刚进 UART。切 RS-485 方向或关闭外设必须选对线路完成事件。

电平与流控

MCU UART 通常是逻辑电平，不能直接与 RS-232 的电气电平等同；RS-485 需要收发器与方向控制。RTS/CTS 可在兼容双方驱动下对接收能力施加硬件背压，软件协议也可用信用控制。仅有更大的环形缓冲不保证无限连续数据不会丢。

推演与反例

从波形推导有效吞吐

8N1 每个字节包含 1 个起始位、8 个数据位和 1 个停止位，共 10 bit。115200 bit/s 对应理想 11520 B/s，一个字节约 86.8 μs，69 字节约 5.99 ms；协议头、CRC、确认、空闲间隔再降低业务吞吐。若增加校验位或停止位，分母也要改变，不能始终用波特率除以 8。

为什么不能背一个通用误差百分比

接收端检测起始沿后按自己的时钟取样，频差会在一帧内累积；允许误差取决于数据位数、过采样与判决方式、发送/接收时钟精度及边沿质量。具体器件的数据手册给出条件，不能把某个经验值外推到全部 UART。TTL UART、RS-232 和 RS-485 的电平与驱动也不同，名称带串口不代表能直接接线。

继续追问

69 字节在 115200、8N1 下最少多久？

忽略间隔和软件延迟，69×10/115200≈5.99 ms；这是串行发送时间下界，不是完整命令往返时延。

UART 全双工是否表示应用可以随意并发写同一个发送口？

硬件收发可以独立，但多个软件发送者的字节仍可能交错。帧发送应由同一个所有者串行化，或用明确互斥和整帧队列保证顺序。

T073 原理问答

DMA 解决什么问题，为什么还需要中断和缓冲？

DMA 由硬件在外设与内存之间搬运数据，减少 CPU 逐字节干预；CPU 仍负责配置、缓冲所有权、完成事件和错误恢复。DMA 提高搬运效率，不自动提供协议边界或无限容量。

原理与成立条件

普通、循环与双缓冲的差别

普通模式到计数结束停止；循环模式到末尾自动重装并从头覆盖；双缓冲/乒乓思想让硬件写一块、软件处理另一块，但是否硬件原生支持取决于 DMA 型号。循环不是自动安全队列，消费者必须赶在下一轮覆盖之前完成复制或处理。

所有权比传指针更重要

DMA 正在使用的 TX 缓冲必须保持不变且有效，RX 缓冲可能随时被硬件覆盖。真正零拷贝需要可证明的借用期限、可暂停的生产端或可归还块池；只把环形缓冲地址发给任务，任务稍晚处理就可能读到下一轮数据。取消、超时与重启时也要确定 DMA 已停止访问。

缓存一致性不能泛化

无数据缓存的 Cortex-M3 不存在某些高端 MCU 的 D-cache 维护问题；带非一致性缓存平台上，DMA 与 CPU 可能读到不同副本，需要按方向 clean/invalidate、对齐缓存行，并避免误丢同一行其他脏数据。内存屏障和缓存维护功能不同，不能用 volatile 替代。

推演与反例

一次 DMA 传输有哪些参数

请求源决定何时搬，源/目的地址与是否递增决定搬到哪里，数据宽度和计数决定每次及总量，普通/循环模式决定结束后是否重装。地址宽度不匹配可能破坏相邻内存，外设请求映射也因系列而异。DMA 会占用总线，因此即使 CPU 指令数减少，也要考虑仲裁对访问延迟的影响。

TX 的两个完成点必须区分

DMA 传输完成通常表示最后一个数据已交给 UART 数据寄存器，不表示最后一个停止位已经离开引脚。UART TC 才对应更后面的线路发送完成条件。若要切换半双工方向或关闭外设，必须等正确事件；缓冲释放最早能在哪个事件发生，也应按驱动是否还会访问它来证明，不能仅靠变量名 complete。

继续追问

DMA 完成中断里立即释放 UART TX 缓冲是否一定正确？

需看 DMA 是否已不再访问以及上层是否还需该帧重发；若要切总线方向，还必须等 UART TC，不能把两种完成事件混淆。

启用 DMA 后还能忽略中断吗？

只有明确采用轮询且轮询延迟有界时才可能；通常仍需要半传输、完成、IDLE 或错误通知来安排消费。搬运与消费是两条独立进度。

T074 原理问答

循环 DMA 加 IDLE 怎样计算新数据，IDLE 是帧结束吗？

循环 DMA 把内存当环持续写，IDLE、半传输和完成事件只报告接收进展。软件根据上次处理位置与本次位置取新增区间，再把字节交给协议解析器；IDLE 不是通用帧结束标记。

原理与成立条件

由位置求增量

设缓冲大小 N，上次处理位置 old，本次位置 pos。未回绕时处理 [old,pos)，回绕时处理 [old,N) 与 [0,pos)。HAL 回调 Size 常是本次有效数据终点，不是自上次回调新增字节数；具体含义要看 HAL 版本。把每次 Size 都从数组 0 复制会重复处理旧数据。

相同位置存在歧义

pos==old 可能是重复通知，也可能已经完整绕了一圈甚至多圈。只保留模位置无法还原丢失的圈数，必须保证服务足够及时或另外跟踪单调生产进度。N 与 0 代表同一物理位置却可能表达不同边界，过早归一化可能在 TC/IDLE 相邻时重复搬运。

从 DMA 到任务的两级容量

ISR 把增量复制进软件流缓冲后，DMA 区可继续覆盖，但软件缓冲仍可能满。必须检查实际接受字节数并记录丢失；发生丢失时解析器需要重新同步，不能继续声称收到完整数据。若多个 ISR 可重入同一写者状态，还需串行化 old 的更新。

推演与反例

回绕区间怎样算才不会漏一段

缓冲长度 N，上次位置 old=50，本次 pos=10，新增区间是 [50,N) 加 [0,10)；若 pos≥old，则是 [old,pos)。但 old==pos 有歧义：既可能没有新字节，也可能硬件已经绕过整圈。仅保留模 N 的位置无法知道发生过几圈，必须通过及时处理中断、累计代数或其他设计排除覆盖。

HAL 回调参数必须看接口契约

一些 Receive-to-idle HAL 回调的 Size 表示当前数据位置，可能等于 N，不是“本次新增长度”。把它直接当长度追加会重复旧数据；把 N 简单变成 0 又要防止相邻 TC/IDLE 通知对同一末尾产生重复处理。具体事件组合与回调次序需核对所用 HAL 版本，并测试半满、全满、回绕与紧邻 IDLE。

继续追问

把 DMA 缓冲从 64 改成 128，问题就结束了吗？

只是扩大覆盖前的时间预算；仍要检查回调位置、软件短写、最长服务间隔和持续输入，不能用容量替代时序证明。

能用“缓冲足够放一帧”证明安全接收吗？

不能。生产者可能连续发多帧，消费者也可能长时间得不到运行；容量证明要基于最坏消费停顿与到达速率，帧最大长度只是其中一个边界。

T075 原理问答

怎样计算 DMA 与软件缓冲容量，证明不会被覆盖？

缓冲能否不溢出，取决于到达数据减去已消费数据的最大积压。必须分别分析硬件 DMA 环和软件队列：前者可能被覆盖，后者可能拒绝或部分接收，扩大其中一个不自动修复另一个。

原理与成立条件

为什么半缓冲时间也重要

若软件依赖半满/全满事件搬运，回调发出时已有一半数据待处理。等到它被延迟到下一次覆盖时，那块数据已经不安全。需要分析最早未处理字节距离硬件下一次写回还有多久，不能总拿整个 N/r 当每次 ISR 的可用延迟。

CPU 关中断与硬件接收不同步

临界区延迟 DMA/USART 回调，DMA 仍可能持续写 RAM。等 CPU 恢复后，位置看似合法，但旧圈数据已经消失；CRC 只能发现部分破坏，不能恢复丢掉的命令。消费者任务同样需要及时排空软件缓冲，两个容量不能简单相加成一个保证窗口。

从分析到方案

测最大不可服务区及实际输入突发，再选择缩短临界区、定时器捕获传感时序、增大缓冲或加字节级流控。帧级窗口限制只约束命令数量，不必然限制瞬间字节突发。零拷贝如果延长消费者持有时间，反而可能使覆盖约束更难满足。

推演与反例

把中断屏蔽时间换算成字节

115200、8N1 时约每 86.8 μs 来 1 字节。64 字节环一圈约 5.56 ms，半环 32 字节约 2.78 ms。若处理每半环一次，回调被延迟几毫秒就可能接近下一次覆盖；准确余量还取决于进入临界区时 DMA 已写到哪里。以上是理想满速输入的预算示例，不是测得的中断上限。

软件缓冲还要覆盖慢消费者

即使 ISR 及时把数据复制进软件缓冲，命令任务在等待传感器转换期间仍可能不消费。容量需要覆盖这段等待中的最大输入，或者由窗口/信用限制发送方。若发送 API 只接收部分字节，必须记录实际返回长度并恢复分帧，不能更新读书签后假定全部交接成功。单纯增大缓冲只能吸收有限突发，长期输入快于消费仍会满。

继续追问

69 B 帧超过 64 B DMA 为什么有时正常？

ISR 和任务可在整帧到完前处理前半段，所以单帧不必全部同时驻留；出现长临界区或突发时，时序条件不满足才暴露丢失。

指针队列是不是自然的零拷贝优化？

不是。DMA 下一圈会重写原地址，指针仍有效但内容已变。需要可转移所有权的块池/双缓冲、回收协议与流控，先证明数据寿命，再比较复制收益。

T076 原理问答

UART 的 ORE、FE、NE 出错后，为什么需要恢复 DMA？

ORE 表示接收数据未及时取走导致覆盖风险，FE 与帧格式/停止位有关，NE 与噪声检测有关。恢复不仅要清错误位，还要恢复 UART、DMA、驱动句柄和软件书签的一致状态。

原理与成立条件

UART 错误要区分原因

FE 常指停止位采样不符合格式，NE 反映噪声检测，ORE 表示前一数据未及时转移而新数据到达。波特率、电平、接线与服务不及时都可能参与。软件队列溢出和 DMA 环覆盖可能没有对应 UART 硬件错误标志，因此只统计 ORE 不能涵盖全部丢字节。

清标志与恢复接收是两步

按芯片手册的序列清错误后，还要确认 DMA 请求、相关中断和 HAL 状态是否仍启用。某些 HAL 版本把 DMA 接收错误视为需要停止当前接收，回调后若不重挂，任务仍运行但数据再也不进来。错误处理必须对照实际版本状态机，不能从别的系列复制几行清标志代码。

恢复要同步软件位置

DMA 从头重启时，软件 old_pos、剩余长度和解析残帧必须有一致的处理规则。保留旧位置会重复或跳过字节；损坏半帧应让解析器重新同步。重挂 API 可能返回 BUSY/ERROR，应有有限重试或任务级恢复，不能在 ISR 无限循环。

把诊断分层保存

记录硬件错误类型、DMA 重启次数及失败、软件短写、CRC 错误与命令超时，再关联时间。一个总错误计数无法区分物理链路差与任务调度慢。恢复成功也不能抹掉证据，否则故障表现为偶发变慢却没有根因信息。

推演与反例

为什么“清了错误标志”仍收不到

驱动错误路径可能已关闭 DMA 请求、IDLE 中断并把接收状态退回 READY。应用只清一个寄存器位而不重新启动接收，链路就会保持静默。反过来，直接重启 DMA 但保留旧位置，也可能把重装后的新数据与旧半帧拼接。F1 的 SR/DR 清除顺序及 HAL 错误处理细节要按对应版本确认。

有限恢复要保留可诊断结果

可计数错误、清理不可信的接收残段并尝试重启，记录重启是否成功；连续失败时交由任务以退避和期限处理。ISR 中无限恢复循环会阻塞整个系统。错误期间已经丢失的字节不能被重新开 DMA 找回来，只能靠协议重同步和上层重传弥补。

继续追问

命令任务还在签到，为什么 watchdog 没发现接收坏了？

任务活性不等于外设活性；需要检查最近 RX 进度、恢复结果及业务反馈，不能只看循环是否继续执行。

看到 ORE 就能断定 CPU 太慢吗？

不能。还可能是长关中断、DMA 未启动或映射错误、优先级配置、重启窗口和驱动状态异常。应结合波形、DMA 计数器、错误发生时刻与消费者进度定位。

T077 原理问答

I2C 为什么必须开漏，上拉电阻怎么影响时序？

常见 I2C 使用开漏/开集输出和上拉，实现多个设备只能拉低、释放后回高的线与行为。这支持 ACK、仲裁与时钟拉伸，也使上升沿由电阻和总线电容决定。

原理与成立条件

开漏如何形成共享总线

I2C 的 SDA/SCL 通常由开漏输出配上拉构成，参与者可拉低或释放；任意一方拉低时总线为低。这样允许 ACK、时钟拉伸和多主仲裁，不会像两个推挽输出分别驱高/低那样直接对抗。释放不等于主动驱高，实际高电平取决于上拉、电容及是否还有设备拉低。

拉伸与仲裁

支持拉伸的从机可把 SCL 继续拉低，主机应观察实际电平而非只写“释放 SCL”；多主仲裁通过发送同时读取 SDA 实现，发送高却读低者在相应条件下失去仲裁。并非所有模式、控制器和设备都支持全部能力，需遵从双方速率及接口约束。

推演与反例

上拉电阻为什么既不能太大也不能太小

电阻太大，RC 充电使上升沿变慢，采样时可能还未达到高电平门限；太小则低电平灌电流过大。常用估算 Rmax≈tr/(0.8473×Cb)，Rmin≈(VDD−VOLmax)/IOL，要使用器件允许的电流、总线模式上升时间和实际电容。布线、连接器及探头都会增加电容，不能只照抄一个 4.7 kΩ。

数据什么时候允许变化

普通数据位在 SCL 高电平期间保持稳定，SCL 低时改变；SCL 高时 SDA 的下降/上升分别形成 START/STOP。每 8 位后还有第 9 个 ACK 时钟，由接收方决定应答。某些器件可把 SCL 拉低延长等待，因此主机释放 SCL 后还需按系统能力确认它真的变高，输出寄存器写高不等于线上已经高。

继续追问

GPIO 配了内部上拉，就一定可以不放外部电阻吗？

不一定。内部上拉常较弱且离散，可能不满足总线电容与速度要求；要按数据手册和实测上升时间判断。

I2C 可以用推挽主动输出高吗？

普通共享 I2C 的这些信号阶段不应这样做，否则另一器件拉低时形成电气争用，破坏仲裁与拉伸。特殊模式须按专门规范设计，不能套进普通设备连接。

T078 原理问答

I2C 七位地址如何编码，传感器转换与读取怎样配合？

I2C 七位地址是设备身份，线上第一个地址字节通常由地址左移一位再附加读写位形成。驱动 API 可能要求七位值，也可能要求已移位值；正确性取决于接口契约，不取决于哪一种写法更像地址。

原理与成立条件

7 位地址与地址字节

I2C 常用 7 位从地址，在线上传输时左移一位并加 R/W 位，形成首个地址字节。驱动 API 接受未移位地址还是已移位值由接口规定；把 0x23、0x46、0x47 混称同一个地址却不说明层次，是常见 NACK 原因。分析仪往往显示 7 位地址，应核对显示选项。

转换与读出是不同阶段

数字传感器接到测量命令后，需要积分/转换时间，再提供寄存器结果。I2C 传输很快不代表新的物理测量已完成；过早读取可能取得旧数据。连续模式与单次模式的启动、更新和功耗语义不同，重复下发模式也会影响结果新鲜度，应按芯片手册处理。

BH1750 数值换算的条件

默认测量时间设置下，常规高分辨率模式读取高字节在前的 16 位原始码，典型换算 lux=raw/1.2。高分辨率 mode2 或修改 MTreg 会改变比例与时间，不能始终套这个除数。数据手册的分辨率、精度、典型时间和最大时间含义不同，整数输出也不意味着误差只有 1 lx。

驱动应输出数据与有效性

读取成功、量程溢出、转换未完成和总线错误应分别表达；不要把错误原始码直接换算后当有效光照。把浮点结果压到 u16 时需定义舍入和饱和，不能依赖越界转换。上层应知道采样时间和有效状态，才能正确展示与报警。

推演与反例

用 0x23 检查线上字节

七位地址 0x23 的写地址字节为 0x46，读地址字节为 0x47。若 HAL 要求传入左移后的地址而应用传 0x23，或库已经左移而应用又左移一次，就会访问错误地址。抓波形时还要确认分析仪显示的是七位地址还是完整地址字节，避免把正常 0x46 误判为地址配置变了。

数值读取前为何要等转换

命令发送成功只说明器件收到了配置，不表示新测量已完成。以默认测量时间寄存器的 BH1750 高分辨率模式为例，典型/最大转换时间和 raw 到 lux 系数都由手册规定；默认常用 raw/1.2，修改测量时间后换算也应调整。等待可以让任务阻塞释放 CPU，但若同时持有传感器锁，其他查询仍会被该转换时长挡住。

继续追问

读到 0 lx 是否说明传感器坏了？

可能是真实黑暗，也可能未转换、配置错误或错误被当成零。需要结合事务返回、模式、转换等待和有效标志判断。

连续测量模式下每次重发模式命令一定必要吗？

未必。要按器件行为判断是否重启测量或改变新鲜度；可设计缓存与定期更新，但不能把收到两个字节就等同于获得刚发生的测量。

T079 原理问答

SDA 卡低时为什么发九个时钟，哪些故障救不了？

SDA 卡低时发送最多九个 SCL 脉冲，是试图让停在一个字节中间的从机完成剩余位并释放总线。它是有前提的总线清理，不是能修复所有 I2C 故障的通用复位。

原理与成立条件

SDA 卡低为何可能恢复

从机可能停在发送某一位或等待时钟，主机复位后丢失事务状态。主机释放 SDA，提供最多 9 个适当时钟，可让从机推进到字节/ACK 边界并释放线路，再尝试生成 STOP。这针对协议状态卡住，不会修复短路、供电异常或损坏设备。

SCL 卡低不能靠写高解决

开漏主机写高只是释放，若从机持续拉低 SCL，时钟并未真正产生。应读取实际 SCL 并设置有限等待；确认硬件不支持恢复或超过期限时，可按设备方案复位/断电恢复。不能因为循环执行了 9 次 GPIO 翻转就宣称总线已解锁。

恢复时必须独占总线

停止当前 I2C 事务与相关 DMA/中断，防止其他任务同时访问，再将引脚切到合适 GPIO 模式执行恢复。STOP 是在 SCL 确实高时释放 SDA；恢复后重建外设配置，并重新初始化可能丢状态的传感器。应校验总线空闲与每个初始化返回值。

控制重试避免恢复风暴

一次普通读失败后可进行有限恢复和重试，连续失败向上报告并退避。每次调用都无期限尝试，会让一个坏设备长期霸占总线和互斥量。保留首次错误与恢复结局，便于区分时序问题、设备复位和物理故障。

推演与反例

为什么是九个而不是无限个

一个常见传输单元是 8 数据位加 1 ACK 位，主机复位可能让从机仍停留在其中某一位。释放 SDA、产生时钟并观察线路，可以推进残留状态，再构造 STOP 结束事务。前提是 SCL 能被拉高、从机仍按时钟工作；若短路、供电异常或器件永久拉低，继续打时钟并不能解决。

硬件恢复与软件恢复要一起做

暂时停用外设、把引脚切到合适开漏模式、进行有界清理、恢复复用与外设配置，然后让应用知道本次事务失败并决定是否重试。不能保留旧接收数据并标成有效，也不能把恢复时的 GPIO 操作与另一个任务的正常 I2C 事务并发执行。涉及多个控制器时还要避免把合法传输误判为卡死。

继续追问

为什么不在任何 NACK 后都立刻发送 9 个时钟？

NACK 也可能是地址错、设备忙或正常的结束语义。应先识别错误类型和总线状态，避免打断本可正确结束的事务。

SCL 本身一直低时怎么办？

先区分合法拉伸与超过期限的异常；若无法释放，应按器件能力使用硬件复位、断电恢复或报告故障。规范中的九时钟方案主要针对 SDA 卡低且 SCL 可控制的情形。

T080 原理问答

DHT11 如何区分 0 和 1，为什么不能用普通毫秒延时？

DHT11 用高电平持续时间区分 0 和 1，必须测量或采样微秒级波形。毫秒任务延时无法定位判位窗口；同时每段等边沿都要有界，防止断线把 CPU 永久困住。

原理与成立条件

DHT11 怎样编码数据

主机先按规格拉低启动，再释放线路等待从机响应，随后接收 40 位数据。每位低电平作为分隔，高电平持续长度区分 0/1，最后一字节用于校验前面数据。不能像 UART 一样只给出固定波特率，正确解码依赖微秒级边沿与脉宽判断，以及匹配实际传感器版本的数据格式。

为什么采用超时边沿等待

如果传感器未接、线被拉住或时序错，等待某个电平的 while 可能永久不退出。每个阶段应有合理上限，失败后释放总线并返回状态；校验正确后还要检查小数位与范围。总超时由多阶段上限累计，不能只看某一个等待的 100 μs。

忙等与关中断的取舍

DWT 可按 CPU 周期做短延时，但中断会拉长软件采样时刻；关中断能减少一类抖动，却伤害全系统响应，且更高紧急度异常未必被屏蔽。更稳健的高负载方案可用定时器输入捕获记录边沿或 DMA 搬捕获值，代价是额外资源和解码复杂度。

传感器限制不能被软件绕开

V1.3 要求读取间隔大于 2 s，上电后先等稳定；读到的还是上一轮测量结果，频繁读不能无限提高新鲜度。该版湿度小数注明为 0，温度可有小数，温度低字节最高位另作负号。其他实物/修订应分别核对，不能把协议小数字段的存在等同传感器真实精度，或统一宣称 DHT11 只能报整数。

推演与反例

从两个时间区间推导采样点

所引奥松 DHT11 V1.3 手册中，0 的高电平为 23–27 μs、1 为 68–74 μs，选择上升沿后约 40 μs 采样，可在理想条件下区分二者。真正余量还要扣除边沿检测延迟、函数执行、中断抢占和时钟误差。若采样点被推到 70 μs，长脉冲也可能已回低，算法便失效。应以实物版本波形和手册确认，而不是只背“0 是 26、1 是 70”。

校验成功仍不等于数据新鲜且可表示

五字节数据含温湿度字段与累加校验；V1.3 对读取间隔、上电稳定和上一轮测量值有说明，温度低字节还带负号约定。解析应检查版本、符号、小数格式及目标数值范围。一个无符号温度协议不能靠强转发送负温；应修改格式或显式报告不支持，不能悄悄变成很大的正数。

继续追问

为何不能把 18 ms 启动低电平和位采样全部关中断？

启动阶段通常不需要微秒级 CPU 独占，把毫秒等待一起屏蔽会显著扩大串口与 Tick 延迟。应分别按时序严格程度选择等待方式。

关中断采样能否彻底消除时序问题？

只能屏蔽指定范围的抢占，还受更紧急异常、代码执行和电气波形影响，并把延迟转移给 UART、Tick 等路径。更高负载时可考虑定时器输入捕获等硬件计时方案。

T081 原理问答

CAN 的仲裁、确认、错误状态与位时序如何工作？

经典 CAN 是按标识符竞争访问的广播总线。控制器处理帧与仲裁，收发器负责差分物理信号；显性位覆盖隐性位，使优先级较低的发送者能退出而不破坏获胜帧。

原理与成立条件

CAN 控制器与收发器的分工

经典 CAN 是多主广播总线，控制器处理位时序、帧、仲裁、校验与错误状态，收发器把逻辑电平转换为 CANH/CANL 差分信号。标识符描述消息并参与优先级，不天然等同节点地址。标准帧 11 位 ID、扩展帧 29 位 ID，经典 CAN 数据字段最多 8 字节；CAN FD 的能力不能套到传统 bxCAN。

非破坏仲裁为什么成立

显性 0 能覆盖隐性 1，节点发送时同时监视总线；在仲裁字段发送隐性却读到显性的节点退出发送，获胜者继续，报文不必被所有竞争者同时破坏。相同帧格式下较小 ID 通常更优先；标准/扩展竞争还涉及 SRR/IDE 等位，不能只把两个不同长度 ID 当整数比较。

ACK 与故障限制

正确接收的节点可在 ACK 槽给出显性确认，它不表示目标应用已经消费或执行。CRC、位监视、填充等机制检测错误，错误计数驱动 error-active、error-passive 和 bus-off 等状态。恢复策略需要诊断物理层与波特率，不能无限自动重连而掩盖持续故障。

位时序与拓扑为何重要

波特率由时钟、预分频和时间段组成，采样点与重同步跳宽影响对传播延迟和时钟误差的容忍。高速 CAN 常在总线两端各接匹配终端电阻，支线过长、星形拓扑和接地问题可造成反射/共模困难。只让两个节点“设置同样波特率”不足以保证所有长度和负载下稳定。

推演与反例

按位仲裁怎样保证非破坏

两个节点同时发，都会读回总线；发送隐性 1 却读到显性 0 的节点，在仲裁字段退出发送，剩余节点继续。相同帧格式下较小 ID 通常更优先，但标准帧与扩展帧混合时还涉及 IDE/SRR 等位，不能直接把两个不同长度的 ID 当普通整数比较。仲裁优先级也不保证低优先级帧不会长期等待，高负载下仍需总线调度预算。

ACK、重传与 bus-off 的关系

正常接收并验证帧的节点可在 ACK 槽给出显性确认，这不表示目标应用已消费。物理错误、位错误和缺少 ACK 等会影响错误计数，控制器可从 error-active 转到 error-passive，严重时进入 bus-off。恢复应检查终端电阻、波特率、采样点、时钟与接地；自动重传不停并不等于业务仍在有效运行。

继续追问

一个 CAN 节点单独发送却不断重发，可能为什么？

正常发送模式下没有其他正常接收节点提供 ACK 会产生 ACK 错误；应检查是否需要环回测试、另一节点、终端、位时序及控制器错误状态，不能只怀疑发送函数。

波特率一样为什么还可能通信失败？

位时间还包含不同时间段、采样点和重同步宽度，线长与传播延迟也参与容差。仅比较标称 bit/s，不足以证明两端时序兼容。

T082 原理问答

SPI 四种模式怎么判断，为什么错一个边沿会读错？

SPI 的 CPOL 定义时钟空闲电平，CPHA 定义在第一个还是第二个有效边沿采样。要从器件时序图确认数据建立/保持与片选范围，不能只记四个模式编号。

原理与成立条件

SPI 的四根线与传输方式

常见 SPI 由主机提供 SCLK，通过 MOSI/MISO 同步移位，片选区分从机与事务。全双工模式下每移出一位也移入一位，因此只想读寄存器时，主机往往仍需发送命令、地址和 dummy 字节来产生时钟。SPI 没有统一规定所有器件的地址、ACK 和帧格式，必须读从机协议。

CPOL 与 CPHA 怎样判断

CPOL 决定时钟空闲高低；CPHA=0 在相对空闲状态的第一个边沿采样，CPHA=1 在第二个边沿采样，另一个边沿通常用于移出/改变数据。先用“第一/第二边沿”分析，再按 CPOL 转成上升/下降，避免死背四种模式时配错采样点。

片选与频率不只是配置位

从机可能要求片选在命令、地址和全部数据期间持续有效，或要求事务间最小高电平时间。时钟上限受建立/保持时间、主从输出延迟、走线和电平转换器限制，GPIO speed 配得最高不能替代时序校核。多从机 MISO 应按要求在未选中时释放。

DMA 发送完成后的收尾

DMA TC 表示数据搬运结束，移位器可能仍忙；撤片选前应按具体 SPI 外设等待真正完成并处理接收数据/溢出。全双工只发不读可能积累 RX 状态错误。不同 STM32 系列的 FIFO、BSY 和 EOT 语义不同，不能把某一型号收尾顺序当通用代码。

推演与反例

用一对边沿解释模式

CPHA=0 时，接收方在第一个边沿采样，发送方必须在该边沿之前准备首位，之后在另一个边沿改变数据；CPHA=1 时通常在第一个边沿移出数据、第二个边沿采样。CPOL 决定这两个边沿分别是上升还是下降。双方错配时可能读到相邻位或边沿上的不稳定电平，低速偶尔可用也不是正确配置的证明。

全双工移位为什么也要发 dummy

SPI 每个时钟同时推进发送与接收，即使业务只想读取，也常需发送占位字节产生时钟。命令、地址、dummy cycle 和结果之间的片选保持由器件协议规定。DMA 搬完不一定等价于 SPI 最后一位结束，拉高 CS 前还要按外设完成条件处理，尤其最后一次读写和 FIFO 排空。

继续追问

SPI 第一个字节总是错，其余正常，先查什么？

检查 CPHA、片选到首个时钟的建立时间、首字节是否及时写入、dummy 数量及从机命令格式；用波形对照采样边沿，比盲目降低频率更容易定位。

SPI 有 ACK 和地址吗？

基础 SPI 没有统一的 I2C 式地址与 ACK，通常由片选和设备自身命令协议定义。错误检测、超时与多设备管理要由上层补充。

依据与核对范围

T083 原理问答

ADC 分辨率、采样时间、DMA 与滤波怎么一起分析？

ADC 位数描述量化等级，精度还受参考电压、输入驱动、采样时间、噪声和校准影响。DMA 只搬运结果，不能让一个尚未稳定的采样电压变准确。

原理与成立条件

分辨率不等于精度

N 位 ADC 有 2^N 个量化等级，理想步长约 Vref/2^N；实际还受偏置、增益、非线性、参考噪声和输入噪声影响。用 Vref/(2^N−1) 做端点线性标定是另一种工程换算口径，不能据此混淆理想量化步长。12 位输出不意味着每次都有 12 位有效精度。

采样时间为何受源阻抗影响

采样阶段通过开关给内部采样电容充电，信号源与开关等效电阻形成 RC。阻抗高或采样时间短，电容不能充分接近输入电压，转换结果产生误差。可延长采样、降低源阻抗或加合适缓冲，但滤波、电容与运放稳定性都需一起设计。

采样率、混叠与噪声

信号频率超过采样系统可辨识范围会折叠到低频，采样前的模拟抗混叠滤波不能由采样后的平均完全替代。多次平均可降低某些不相关随机噪声，却不能修复偏置、参考误差或确定性干扰。过采样增加有效位需要噪声/抖动及带宽等前提，不是多读几次就必然增加精度。

定时器触发加 DMA 的边界

硬件触发让采样时刻更稳定，DMA 降低搬运开销；通道扫描仍常按序采样，不代表多通道同时采样。配置时计算采样+转换周期、序列长度与触发频率，防止来不及完成。缓冲半满/全满通知后还要保证消费者及时处理，并校准参考与输入范围。

推演与反例

为什么高源阻抗需要更长采样

采样开关闭合后，内部采样电容通过信号源阻抗和开关电阻充电，电压以 RC 规律接近真实输入。采样结束太早，剩余误差直接进入转换结果；高分辨率要求更小的剩余误差，通常更需要充分建立时间。可延长采样、降低源阻抗或加合适缓冲，但要同时考虑运放稳定性、输入范围与滤波器。

用误差预算区分滤波与校准

N 位 ADC 理想量化步长约为 Vref/2^N，按端点做工程换算可能用 2^N−1，这不改变量化器本身的等级。多次平均可降低某些不相关噪声，不能修复偏置、增益误差、参考漂移或已混叠信号。模拟抗混叠必须发生在采样前；定时器触发减少采样时刻抖动，但多通道扫描仍可能是依次采样。

继续追问

测量值随 CPU 负载变化，应该只改软件平均次数吗？

先查电源/参考耦合、模拟地、采样时序、源阻抗和 DMA/缓存处理，再判断平均能处理哪类随机噪声；稳定偏差需要校准或硬件整改。

DMA 开了后采样率还受什么限制？

采样加转换的总周期、序列通道数、触发频率、ADC 时钟范围及消费者处理能力仍有限制。必须证明上一轮结束且缓冲未被覆盖，再谈吞吐提升。
