# 第一部分:纯面试(通用知识,最重要)

## 主题 A:为什么要异步日志

### A1. 同步日志有什么问题?异步日志怎么解决?

**答题要点**:同步日志是**业务线程自己写盘**——每条日志都要等磁盘 I/O 返回,业务线程被磁盘速度拖住。高并发下大量线程卡在写盘上,吞吐崩掉。

异步日志:业务线程只把日志**写进内存缓冲区**(极快),**一个专门的后台线程**负责把缓冲区批量刷到磁盘。业务线程和磁盘 I/O 解耦,业务线程几乎不等待。

**怎么答出深度**:核心是**把"慢的磁盘 I/O"从业务线程的关键路径上挪走**,换到后台线程。这和线程池"把慢任务挪走"、Reactor"I/O 不阻塞"是同一类思想——关键路径上只留快操作。

**追问:那低频场景还需要异步日志吗?**
不一定刚需。如果系统就 10Hz、日志量很小,同步日志也扛得住。异步日志的价值在**高吞吐/突发**场景。所以选不选要看负载——这是按场景选复杂度。(这一点我在 mock 里没讲好,见第二部分 P3。)

## 主题 B:双缓冲机制

### B1. 双缓冲(double buffering)是怎么工作的?

**答题要点**:准备两块大缓冲区,一块叫 currentBuffer(前端写)、一块 nextBuffer(备用)。
- **前端**(业务线程):日志写进 currentBuffer。写满了就把它移到一个"待写入"列表,把 nextBuffer 顶上来继续写,然后 notify 后端。
- **后端**(刷盘线程):被唤醒(或定时超时)后,把"待写入"列表里的缓冲区**整批**写盘,写完缓冲区回收复用。

**怎么答出深度——双缓冲的关键收益**:前端和后端**操作不同的缓冲区**,所以前端写日志和后端写盘可以**并行**,锁只在"交换缓冲区指针"那一瞬间持有(纳秒级),而不是整个写盘期间。这就是双缓冲比"一把锁锁住整个写盘"快的根本原因。

**追问:为什么是双缓冲不是单缓冲?**
单缓冲的话,后端写盘时前端没地方写、必须等;有第二块缓冲,后端写 A 的同时前端写 B,互不阻塞。实际实现里前端待写列表可能攒多块,后端一次批量刷,进一步摊薄 I/O 次数。

---

### B2. 后端刷盘线程什么时候醒来刷盘?

**答题要点**:两个触发条件,满足任一就刷——
1. **缓冲区写满**:前端写满 currentBuffer 时主动 notify。
2. **定时超时**:即使没写满,也每隔固定时间(如 3 秒)刷一次,用 `cv.wait_for`(带超时的等待)实现。

**为什么要定时刷**:低频时缓冲区半天写不满,如果只等"写满"才刷,日志会在内存里积压很久、迟迟落不了盘——一旦崩溃这些日志全丢。定时刷保证日志最多延迟固定时间就落盘,兼顾"批量效率"和"及时性"。

## 主题 C:相关 C++ 机制

### C1. 日志器常做成单例,Meyers 单例是什么?为什么线程安全?

**答题要点**:Meyers 单例 = 把实例做成**函数内的 `static` 局部变量**:
```cpp
static AsyncLogger& instance() {
    static AsyncLogger logger;  // 首次调用时初始化,且只初始化一次
    return logger;
}
```
**为什么线程安全**:C++11 标准保证**函数内 static 局部变量的初始化是线程安全的**(编译器自动加同步,多线程同时首次调用也只构造一次)。比"双检锁(DCLP)"写法简单且无坑。

**措辞陷阱**:别说"static 变量天生线程安全"。是**C++11 起、函数内 static 局部变量的初始化**线程安全;全局 static、类成员 static 的初始化顺序问题(static initialization order fiasco)是另一回事。说清楚范围。

# 第二部分:和项目挂钩(我具体怎么做的)

### P1. 你的 AsyncLogger 具体参数和结构?

**答**:muduo 风格,缓冲区 4MB 一块、双缓冲(currentBuffer + nextBuffer),前端写满或定时(`wait_for`)触发后端刷盘,后端用一个 `buffersToWrite` vector 收集待写缓冲区批量落盘、写完回收复用。单例用 Meyers 单例。归档在 `src/log/`,main.cpp 里业务路径全部走异步日志写 `/tmp/gateway.log`。

**答**:**前端**实测 740–833 万条/秒(这是业务线程把日志写进内存缓冲的速率,是异步日志的核心卖点——前端几乎不等待)。

### P3. 这个模块 mock 你考了多少?暴露什么问题?

**答**(诚实 + 已分析):M3 mock 我考了 **69 分**,是几个模块里最低的,暴露三个表达问题:
1. **开场缺项目颗粒度**:没讲清"我这网关 10Hz 场景其实同步日志也够,做异步是为了扩展性/学习",上来就讲机制,显得没想清楚为什么要用。

这条是我最该改的诚信/严谨问题:**前端速率我测了(740–833 万条/秒),后端写盘速率我没测,绝不能说成一致。** 现在我会明确区分"测过的"和"没测的"。

### P4. (如果追问)那后端到底能不能跟上前端?
